[4. 최우선 구현 — F01 시간 계약]
시작점:
src/content/prologue.ts의 STAY_UNTIL_BLACKOUT, WAIT_FOR_KNOWN_BLACKOUT,
blackoutMemory.payoff, CH2→CH3 전환, 시간 계산·기억 사용·저장 관련 코드.
보고된 함수·식별자가 현재 트리와 다르면 실제 위치를 확인한다.

사용자 보고서의 확정 제약:
출발 21:23, 이동 약 50분, 정전 00:00, CH3 시작 00:27, CH3 사망 01:06.
실제 offset 원점이 21:23임을 코드와 대조한다. 그 원점이 맞다면 다음 날 자정은 157, CH3 시작은 184, 사망은 223분이다.
자정 이후를 단순 HH:mm 비교로 처리하지 말고 날짜/루프를 구분하는 기존 시간 구조에 맞춘다.

수정 전 경로별 시간 장부를 출력한다:
장면/선택 ID, 진입 시각, 이동·조사·대기 비용, 고정 사건, 종료 시각,
기억·단서 조건, 사건 처리 여부, CH3 진입 가능 여부.
최소 비용·최대 합법 조사·선택 공개 수준이 다른 경로를 포함한다.
선택 순서와 정보 상태가 다르면 같은 장면이어도 필요한 별도 상태로 취급한다.
조합 수가 너무 크면 도달 가능한 상태의 동치 축약과 경계 탐색을 사용하고 제외 범위를 명시한다.

‘자정만 바꾸면 CH2 00:49 → CH3 00:27로 22분 역행’한 과거 반례를 현재 코드에서 재현해 원인을 확인한다.
재현하지 못하면 현재 결함으로 단정하지 말고 조건 차이를 기록한다.

구현 원칙:
- 정전 시각 한 줄만 바꾸거나 표시 시계만 고치지 않는다.
- 루프 리셋 또는 명시된 회상 표현을 제외하고 실제 진행 시간이 역행하지 않는다.
- 모든 비용은 음수가 아니어야 하며 선택·로드·재렌더링으로 중복 부과되지 않아야 한다.
- 대기는 현재 시각과 목표 사건을 바탕으로 계산하되, 이미 지난 사건의 정상 처리 여부도 확인한다.
- 긴 이동/조사로 사건 시각을 넘는 경우 누락·중복 없이 기존 설계에 맞게 처리한다.
- 사건 1회성은 루프와 저장 복원을 고려한다. 다음 루프의 정상 사건까지 막지 않는다.
- CH2 최대 합법 조사 경로와 CH3 00:27을 함께 검사한다.
- 이동 ‘약 50분’의 서사적 의미를 보존한다. 제약을 맞추려고 모든 이동·조사를 0분으로 만들지 않는다.
- min/max로 시계를 강제 덮어쓰거나 하루를 더해 모순을 숨기지 않는다.
- 원문을 몰래 수정하거나 선택을 조용히 삭제·비활성화해 검사만 통과시키지 않는다.

기억 usableFrom70..120은 정전 offset157과의 관계를 실제 코드에서 조사한다.
‘정전 전에 예측·경고·준비에 쓰는 기억’과 ‘정전 발생 시 지식을 검증받는 payoff’를 분리한다.
모든 기억 사용 시작을 157로 늦춰 정상적인 사전 예측 선택을 없애지 않는다.
직접 도착/문자 예측/최소 공개/정확한 공개의 실제 선택 ID와 조건을 대조하고 F04의 실제 획득 기억 기준을 유지한다.

기계적인 비용·대기·사건 처리 수정만으로 확정 원문을 만족시킬 수 있으면 최소 범위로 구현한다.
동시에 만족할 수 없으면 충돌하는 최소 경로·제약 묶음과 원문을 제시한다.
대안별 비용·선택 도달성·기억 효과·서사 영향을 비교하고 해당 창작 결정을 대기로 남긴다. 독립적인 버그·아트·GUI 작업은 계속한다.

수정 전 관찰 수와 수정 후 검증 수를 섞지 않는다. 현재 콘텐츠 수를 확인하며 과거 70장면을 고정 분모로 쓰지 않는다.
앱이 노출하지 않는 내부 값은 상태 로그로 교차 검증하고 GUI에서 보았다고 표현하지 않는다.
시간 계약으로 상태가 바뀌는 검증에는 ‘전후 상태 완전 동일’을 강요하지 말고 의도한 시간 변화와 유지해야 할 기억·소지품·경로를 구분한다.
순수 아트 전후 비교는 같은 코드/계약·같은 논리 저장·동일 선택·동일 화면 조건으로 수행한다.

빨리 넘기는 기능 QA와 독서·연출 검수를 분리한다.
대표 대화/조사 구간은 문장을 실제로 읽고 선택 이유·정보 전달·감정 연결·반복 설명을 확인한다.
대사 누락·연결·노출 오류는 확정 원문 기준으로 고치고, 주관적인 리라이트 제안은 분리한다.
30~45분 완성 체험이나 신규 플레이어의 몰입도를 빠른 입력 기록만으로 통과시키지 않는다.

[6. ComfyUI·Midjourney 병행 제작 — 둘 다 제작 흐름에 포함]
한쪽 도구를 자동 폐기하거나 둘 중 하나만 기본으로 고정하지 않는다.
동일한 brief, 캐릭터 기준, 화풍 기준, 화면 조건으로 결과를 만들고 비교·선별·통합한다.
모든 자산을 반드시 두 모델로 한 번씩 다시 생성할 필요는 없다. 원본이 더 좋으면 보존한다.

Midjourney 트랙:
- 기존 민서 후보 A 및 허용된 기존 원본을 재사용한다.
- 필요한 표정/구도/배경 후보 제작용 구체적 프롬프트, 참조 이미지, 모델별 파라미터를 준비한다.
- Style Reference는 화풍을 위한 것이며 인물 정체성 참조를 대체한다고 가정하지 않는다.
- 현재 사용하는 버전과 해당 버전의 레퍼런스 기능을 공식 문서/설정으로 확인한다. V7의 Omni Reference와 V8 계열 Edit 기능을 혼용하거나 존재하지 않는 옵션을 만들지 않는다.
- 서비스에서 별도로 승인된 자동화 경로와 실제 도구 권한이 확인된 경우에만 그 범위에서 자동 상호작용한다.
- 일반 계정의 무단 자동화는 공식 약관/가이드에 제한되어 있다. 브라우저 자동 클릭이나 비공식 API로 이를 우회하지 않는다.
- 허용 자동화가 없으면 사용자 실행용 MIDJOURNEY_JOBS.md를 만든다. 완성 프롬프트, 필요한 참조 파일, 설정, 원하는 결과, 저장할 프로젝트 전용 경로를 포함한다.
- 이 경우 신규 MJ 생성은 사용자 실행 대기라고 표시하고, 기존 MJ 원본의 활용·로컬 비교와 ComfyUI/코드 작업은 계속한다. 프롬프트만 작성하고 새 MJ 이미지를 생성했다고 보고하지 않는다.
- 사용자 제공/허용 경로로 확보한 결과가 실제 로컬 파일로 존재하면 비교·편집·통합을 이어간다.

ComfyUI 트랙:
- 기본 생성 모델은 Qwen Image 2512다. SDXL로 임의 복귀하지 않는다.
- 실제 체크포인트 파일명·버전·노드·워크플로를 확인한다. Qwen Image 2512와 Qwen-Image-Edit 계열을 동일 모델로 부르지 않는다.
- 일반 img2img, 전용 Edit 모델, 마스크 편집, 알파 추출 중 실제 수행한 작업을 구분한다.
- 전용 편집이 필요해도 설치되지 않은 모델/노드를 있다고 가정하지 않는다. 이번 범위를 넘어 새 설치를 밀어붙이지 않는다.
- 기존 Qwen 워크플로를 복제해 필요한 후보·부분 편집·배경 제작을 수행하고 입력/출력/워크플로를 저장한다.
- 눈매·입술·얼굴 비율을 바꾼 이전 연구 결과를 고려해 전체 얼굴 재생성보다 제한된 편집과 기준 비교를 우선한다.
- BiRefNet은 필요할 때 배경 분리·알파 용도로 사용한다. 알파만 바꾼 작업은 RGB 보존을 실제 픽셀 비교로 확인한다.
- 흰 가운 내부 투명화, 머리카락·안경·소품 유실, 밝은/어두운 배경에서 테두리 번짐을 확인한다.
- 기존 output 하위 폴더 선택 문제를 재확인하되, 권한·보안 설정 변경이나 외부 웹에 임시 공개 업로드로 해결하지 않는다.

공통 제작 규칙:
- 현재 사용량·환경에서 허용된 범위의 소규모 배치로 시작한다. 예: MJ 최대 4후보, ComfyUI 2후보씩 1차 비교, 같은 목표의 재시도는 우선 2회까지.
- 수치보다 결함 개선 근거를 우선한다. 기준 미달을 반복하면 제작량을 늘리지 말고 실패 원인을 정리한다.
- 추가 결제나 다운로드·환경 업그레이드 없이 가능한 작업을 우선한다.
- 외부 서비스에는 제작에 필요한 허용된 시각 레퍼런스만 최소한으로 사용한다. 미공개 시나리오 전체·세이브·코드·계정 정보는 올리지 않는다.
- 서비스의 공개 범위를 확인하며 비공개라고 임의 가정하지 않는다. 자동화·접근이 막히면 우회하지 않고 해당 항목만 분리한다.

[7. 이번 아트 범위와 채택 기준]
먼저 민서 Clinical v03이 쓰이는 CH3·다인 장면·다른 화면 구도를 실제로 확인한다.
실제 시나리오에서 반복 사용되고 효과가 큰 표정 1~2개를 우선 선정한다. 감정 종류는 원문·장면을 읽고 정한다.
무조건 분노/공포/미소 세트를 찍어내거나 모든 캐릭터를 민서에 맞춰 재생성하지 않는다.
전신·후면·새 CG는 실제 사용처와 기존 복장/신발/장면 상태의 근거가 있을 때만 다음 순위로 진행한다.
기준이 없는 고유 디자인을 새로 만들어 이미 확정된 설정처럼 고정하지 않는다.

하나의 brief로 MJ 후보/기존 원본과 ComfyUI 후보·편집안을 연결하고 다음 순서로 판단한다:
1) IDENTITY_LOCK의 얼굴·나이 인상·눈매·입술·머리·체형·복장 유지.
2) 승인된 작품 화풍과 조명·선화·명암의 정합성.
3) 해당 장면의 감정·시간·부상·소지품·지식 상태와 일치.
4) 실제 세로 화면에서 얼굴·중요 소품·대사·선택지의 가림 없음.
5) 투명도·해상도·표시 크기·기준선·로드 비용 등 기술 적합성.

얼굴 정체성 탈락을 ‘예쁘다/고해상도’ 점수로 상쇄하지 않는다.
비교 시트에는 파일명·출처·얼굴 확대·동일 표시 크기·밝은/어두운 배경 합성·판정 근거를 포함한다.
전신을 과도하게 늘리거나 얼굴을 변형해서 크기를 맞추지 않는다.
채택 전 실제 플레이 사용처를 정하고, 채택 뒤 manifest와 필요한 참조만 최소 변경한다.
정상 기준을 만족하는 파생 자산은 자율 통합하되, 확정 v03 원본과 기존 파일은 보존한다.
기준 충족 후보가 없으면 기존 자산을 유지하고 ‘채택 없음’이라고 보고한다.

기술 후처리만 한 이미지와 새 생성 이미지를 구분하며 출처 사슬을 남긴다:
원본 ID/해시 → 실제 생성 모델/설정/참조 → 편집·알파 단계 → 최종 파일/해시 → 연결 장면/참조 → 실제 GUI 결과.
seed나 미제공 설정은 모른다고 기록한다. 재현성이 모델/서버 변경에도 보장된다고 주장하지 않는다.
Clinical 단일 통합·표정별 통합·CH3 다인 구도·전신·CG는 따로 완료 처리한다.

[8. Computer Use, 병렬 작업, 환경 경계]
실제 도구를 호출해 화면 보기와 안전한 입력 가능 여부부터 확인한다. 없는 MCP/앱/모델을 있다고 가정하지 않는다.
UI/아트 검수는 실제 화면을 보고, 반복적인 데이터 접근·코드 수정·검사는 구조화된 도구를 사용한다.
Windows의 같은 데스크톱에서 GUI 담당자는 한 명만 둔다. 여러 에이전트가 동시에 마우스·키보드·같은 파일을 조작하지 않는다.
시간 계약 분석/아트 필요 목록/테스트 검토는 병렬 분담할 수 있지만 변경 소유자를 분명히 정하고 통합 검증은 직렬 수행한다.
‘병행’은 두 제작 트랙을 같은 배치에서 운영한다는 뜻이다. 서로 다른 도구에 같은 클릭을 동시에 보내라는 뜻이 아니다.

Android는 기존 debug APK + 현재 Metro 개발 번들 여부를 확인한다.
패키지 보고값은 com.jungih4982.zerohourgame이며 실제 기기·APK·번들 식별자를 기록한다.
이전 emulator-5580/API35/1080×2400/density420/font_scale1은 비교 기준이다. 해당 시리얼이 현재 다른 기기인지 확인하지 않고 사용하지 않는다.
격리된 테스트 AVD/userdata만 쓰며 기존 사용자 AVD를 초기화하지 않는다.
저장 복원은 격리 기기의 앱을 멈춘 뒤 기존에 승인된 안전 절차를 사용한다. 원본 DB는 보존하고 SQLite 일관성과 파싱한 논리 상태도 확인한다.
시계 계약 변경 후 세이브 비교와 아트만 변경한 세이브 비교의 목적을 구분한다.

blocked by policy, 앱 접근 거부, 파일 URL 권한 제한을 다른 명령·경로·도구로 우회하지 않는다.
같은 거부 동작을 분할하거나 감춰 실행하지 않는다. 정상적으로 허용되는 독립 경로가 있는지 확인하고, 없으면 제한을 보고한다.
기존에 불필요했던 adb reverse를 습관적으로 다시 시도하지 않는다.
새 release APK·iOS 포팅·실기기 배포는 이번 작은 배치의 기본 범위가 아니다.
프로젝트 앱 오류와 Android/GMS/SystemUI 오류를 구분하며 전체 환경 안정성 PASS를 과장하지 않는다.
작업 전용으로 시작한 프로세스만 소유권을 확인해 종료한다. 기존 ComfyUI/Chrome/사용자 개발 서버는 유지한다.

필수 자료는 목적별로 간결하게 정리한다:
- BATCH_REPORT.md: 실제 구현·관찰·제안·미검증과 변경 파일.

- ART_REVIEW/: 기준/후보 비교, 실제 출처, 통합/미채택 이유, 워크플로·입출력, MIDJOURNEY_JOBS.md.

관련 기존 최신 포인터만 갱신하고 내용이 같은 문서를 대량 중복 생성하지 않는다.

최종 보고 순서:
1) F01이 어떤 경로에서 어떻게 해결됐는지, 또는 어떤 확정 제약이 충돌하는지.
2) 실제로 정상 플레이한 시작점·종결점·미검증 분기.
3) 이번 이미지별 MJ/ComfyUI의 실제 역할과 채택 결과. 준비만 한 작업은 실행 완료로 세지 않는다.
4) 변경 파일, 보존 검사, 자동 검사, GUI 검사, 미검증·승인 필요 범위.
5) 정확한 다음 재개점과 다음 안전 작업.

이슈 하나는 ‘관찰 → 원인 → 최소 수정 → 자동 검사 → 해당 실제 화면 재검증’으로 닫는다.
일반 기능/정체성 보존 아트 선택마다 사용자에게 다시 허락을 묻지 않는다.
F01과 이번 작은 통합 단위를 마치면 시간 의존성이 큰 후속 문제부터 진행한다:
손목밴드 재획득·보유 조건, 용어 조기 공개, ORIGIN TRACE 선택의 실제 상태 효과, B1 카트 획득 재현, CH2 확정 원문 대비 누락/축약.
원문 리라이트로 바로 해결하지 말고 실제 구현과 승인 원문을 대조한다.
확인하지 못한 장면·표정·플랫폼을 완료 처리하지 말고, 작업량 대신 실제로 나아진 플레이와 근거를 보고하라.
