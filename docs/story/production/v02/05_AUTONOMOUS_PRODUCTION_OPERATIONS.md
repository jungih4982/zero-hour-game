# ZERO HOUR — AUTONOMOUS PRODUCTION OPERATIONS

이 문서는 Codex Local이 코드 작성뿐 아니라 아트 제작, Simulator/Emulator 플레이, 다중 화면 QA를 자율적으로 반복하기 위한 운영 인계서다. 제작 중에는 실물 iPad를 사용하지 않고, 완성된 출시 후보 빌드의 최종 검수에서만 실물 기기를 사용한다.

## 1. 기본 원칙

Codex는 다음 루프를 한 번만 수행하고 멈추지 않는다.

`구현 → Android 휴대전화 플레이 → iPad 크기 플레이 → 시각·입력 문제 기록 → 수정 → 같은 경로 재플레이 → 회귀 검사`

이미지가 실제 병목일 때는 다음 루프를 추가한다.

`필요 장면 정의 → 기존 에셋 재사용 가능성 확인 → Midjourney 생성 → 후보 비교 → 편집·적용 → 실제 기기 화면 검증`

사소한 디자인 선택은 사용자에게 묻지 않는다. 아래 실제 blocker에서만 멈춘다.

- 로그인 만료, 2단계 인증, CAPTCHA.
- Midjourney 결제·요금제 변경 또는 추가 구매.
- macOS 화면 기록·손쉬운 사용 권한 승인.
- 최종 실물 기기 검수 단계의 iPad `이 컴퓨터를 신뢰`, 잠금 해제, 개발자 모드, Apple ID·서명 확인.
- 기존 시나리오와 충돌하는 새로운 canonical story 결정.
- 데이터 삭제, 저장소 reset/revert/clean, 원격 push.

## 2. 시작 시 환경 감사

작업을 시작할 때 아래를 실제로 확인하고 사용 가능한 표면만 보고한다. 프롬프트에 적혀 있다는 이유로 연결됐다고 가정하지 않는다.

### Mac과 브라우저

- Codex 데스크톱의 Computer Use 기능이 사용 가능한가.
- macOS 화면 기록과 손쉬운 사용 권한이 허용됐는가.
- Chrome 제어 연결 또는 브라우저 확장이 활성화됐는가.
- 사용자가 지정한 Chrome 프로필에서 Midjourney 로그인이 유지되는가.
- 로그인 상태를 확인하기 위해 쿠키, 비밀번호, 브라우저 프로필 파일을 읽지 않는다. 화면에 보이는 상태만 사용한다.

### Android

- Android SDK, `adb`, Gradle/JDK 경로.
- 휴대전화형 Emulator 한 대와 태블릿형 또는 큰 화면 Emulator 한 대.
- 앱 설치·실행·스크린샷·로그·입력 자동화 가능 여부.
- 기존 실행 중인 Emulator가 있으면 재사용한다.

### iOS Simulator

- Xcode 프로젝트/workspace, scheme, bundle identifier.
- iPhone Simulator와 11-inch iPad 크기 Simulator.
- 가능하면 XcodeBuildMCP 또는 동등한 Simulator 자동화 도구.
- 제작 중에는 실물 iPad 연결·설치 상태를 확인하지 않는다.

## 3. Chrome/Midjourney 아트 제작

### 사용 조건

- 기존 에셋의 crop, 배경 찌꺼기, 캐릭터 일관성, 표정 부족이 실제 플레이 화면에서 확인됐을 때만 생성한다.
- 사용자가 로그인해 둔 **Chrome의 Midjourney**를 우선 사용한다.
- Chrome 연결이 없으면 다른 브라우저로 임의 전환하지 않는다. 연결 방법을 blocker로 남기고 코드·QA 작업을 계속한다.
- 로그인 만료나 CAPTCHA는 사용자가 직접 처리해야 한다.
- 추가 결제나 요금제 변경은 절대 자율 실행하지 않는다.

### 생성 순서

1. 실제 화면 캡처와 장면 대본을 보고 필요한 자산을 한 문장으로 정의한다.
2. 기존 에셋으로 해결 가능한지 먼저 확인한다.
3. 캐릭터라면 기준 얼굴·머리·체형·의상 레퍼런스를 함께 사용한다.
4. 모바일 세로 화면의 머리 여백과 dialogue safe zone을 프롬프트에 명시한다.
5. 한 번에 대량 생성하지 않고 한 장면 또는 한 캐릭터 표정군 단위로 생성한다.
6. 후보를 원본 상태로 내려받고 프로젝트 밖 임시 위치에서 검토한다.
7. 채택본만 프로젝트 에셋 규칙에 맞춰 복사·편집·등록한다.
8. 흰색 테두리, 반투명 halo, 잘린 머리·손, 다른 화풍, 잘못된 광원을 확대 확인한다.
9. Android와 iPad 화면에서 실제 대사와 함께 재검증한다.

### 캐릭터 일관성

- 같은 인물의 얼굴형, 눈매, 헤어라인, 체형, 의상 기준을 고정한다.
- 기본 프레이밍은 인물별로 통일한다. 전신과 흉상이 이유 없이 섞이지 않게 한다.
- 필요한 표정은 `neutral`, `watchful`, `alarmed`, `suspicious`, `confrontational`, `exhausted` 순으로 확충한다.
- 전화 통화 중인 서윤은 실제 현장 인물과 같은 위치에 세워 두지 않는다. 통화 전용 연출이나 화면 분리 규칙을 따른다.
- 채택 이유와 사용 장면을 에셋 manifest 또는 제작 기록에 남긴다.

## 4. Android 자율 플레이 QA

### 기준 기기

- 휴대전화: Pixel 8급 세로 비율을 기본으로 한다.
- 큰 화면: Android 태블릿 또는 폴더블의 큰 세로 창을 추가한다.

### 직접 수행할 경로

- 새 게임 → 튜토리얼 → 첫 통화 → 병원 도착.
- 대사 탭 완료/다음 진행.
- 선택지 출현과 48dp 이상 터치 영역.
- 뒤로가기 → 종료가 아니라 게임 메뉴 또는 확인 동작.
- 저장 → 앱 종료 → 이어하기.
- 조사 → 단서 강조 → 추론 → Foreknowledge 사용.
- 첫 죽음 → Loop 2 → 기억 선택 해금.
- 현재 구현한 장의 모든 신규 분기.

### 수집할 증거

- 주요 장면 전후 스크린샷.
- 앱 로그와 크래시/멈춤 여부.
- 화면 크기, OS/API, 방향.
- 잘림, safe area, 상태바·navigation bar, 키보드, 대화 가독성.
- 실제 입력으로 재현한 경로와 수정 후 동일 경로 결과.

## 5. iOS Simulator와 iPad 크기 QA

### Simulator

- iPhone 세로 화면과 11-inch iPad 크기를 모두 사용한다.
- 가능하면 XcodeBuildMCP로 project/scheme/simulator를 탐색하고 같은 설정을 반복 사용한다.
- 앱을 빌드·설치·실행한 뒤 접근성 트리를 먼저 읽고 탭·입력·스크롤한다.
- 좌표 탭이 필요하면 해당 컨트롤에 접근성 label/id를 추가할지 검토한다.
- 스크린샷, Simulator 로그, 필요하면 LLDB를 사용한다.

### iPad 전용 검수

- 메인 타이틀과 배경 이미지가 가로·세로 모두 잘리지 않는가.
- 대화 영역이 화면 왼쪽에 작게 몰리지 않는가.
- 글자 크기와 줄 길이가 휴대전화 값을 단순 확대·축소한 결과가 아닌가.
- 캐릭터 머리와 손, 2인 대화 구도가 안전 영역 안에 있는가.
- 메뉴, 인물도감, 저장 화면의 최대 폭과 여백이 태블릿에 맞는가.
- Split View 또는 넓은 창에서 레이아웃이 무너지지 않는가.

## 6. 실물 iPad 최종 검수

실물 iPad 검수는 다음 조건을 모두 만족한 **출시 후보 빌드**에서만 수행한다.

- Android 휴대전화·큰 화면 회귀 통과.
- iPhone·11-inch iPad Simulator 회귀 통과.
- 전체 시나리오 진행, 저장·이어하기, 엔딩 경로 검증 완료.
- 저장소 기본 테스트, 타입 검사, 빌드 검사 통과.
- 더 이상 일상적인 UI 수정이 반복되지 않는 안정 마일스톤.

그전에는 실물 iPad 빌드·설치·연결 확인을 하지 않는다. 실물 기기 문제로 제작 루프를 중단하지 않는다.

최종 단계에서 실물 iPad가 USB 또는 네트워크로 연결되고 신뢰·개발자 모드·서명이 준비돼 있으면 Codex는 빌드, 설치, 실행, 로그 수집을 시도할 수 있다.

다만 다음은 자동 완료를 보장하지 않는다.

- iPad 잠금 해제와 `이 컴퓨터를 신뢰` 승인.
- 개발자 모드 활성화 뒤 기기 재시작 확인.
- Apple ID 로그인, 인증서, 프로비저닝 프로파일 승인.
- 기기 화면의 수동 탭이 필요한 테스트.

실물 iPad UI를 자율 테스트하려면 XCUITest 또는 접근성 기반 UI 테스트 경로를 프로젝트에 마련한다. Mac 화면을 제어할 수 있다는 사실만으로 iPad 화면을 직접 자유롭게 누를 수 있다고 가정하지 않는다.

최종 실물 기기 설치가 막히면 다음처럼 처리한다.

1. 이미 완료한 11-inch iPad Simulator 회귀 결과를 보존한다.
2. 빌드·서명 오류를 수집한다.
3. 사용자가 해야 하는 한 단계만 정확히 blocker로 남긴다.
4. 사용자가 처리한 뒤 같은 빌드를 재사용해 설치를 이어간다.

## 7. 다중 화면 회귀 매트릭스

안정 마일스톤마다 다음 네 표면을 기준으로 한다.

| 표면 | 필수 검수 |
|---|---|
| Android 휴대전화 | 기본 세로 composition, 입력, immersive, 저장/복귀 |
| Android 큰 화면 | 최대 폭, 여백, 메뉴·도감, character scale |
| iPhone Simulator | safe area, notch/Dynamic Island, 대화·선택지 |
| 11-inch iPad Simulator | 태블릿 typography, crop, 2인 구도, 메뉴 |

실물 iPad는 출시 후보의 최종 검수에서만 다섯 번째 표면으로 추가한다. Simulator 검증을 실물 검증으로 허위 보고하지 않는다.

## 8. 자율 수정 우선순위

실제 플레이에서 다음 순서로 처리한다.

1. 진행 불가, 입력 무시, 저장 손상, 크래시.
2. 대사·선택지 잘림, safe area, 뒤로가기 종료.
3. 장면 이해를 막는 튜토리얼·단서 피드백 부족.
4. 캐릭터 crop, 흰 테두리, 전화 연출 오류, 표정 반복.
5. 선택 결과가 느껴지지 않는 게임플레이.
6. 배경·조명·메뉴의 프로토타입 느낌.
7. 신규 아트와 세부 연출.

시각 문제를 새 이미지로 덮기 전에 레이아웃·crop·asset cleanup으로 해결 가능한지 확인한다.

## 9. 마일스톤 보고

보고에는 주장 대신 증거를 남긴다.

- 직접 플레이한 기기/Simulator와 화면 크기.
- 재현한 장면과 선택 경로.
- 수정 전후 스크린샷.
- Midjourney에서 생성한 후보와 최종 채택 에셋.
- 빌드·테스트·로그 결과.
- 실물 기기에서 확인한 것과 Simulator에서만 확인한 것을 구분.
- 로그인·권한·서명 등 실제 blocker.
- 현재 git status. 자동 push와 reset/revert/clean은 금지.

## 10. 자율 작업 시작 문장

새 Codex Local 작업의 첫 프롬프트에는 다음 의도를 포함한다.

> 사용자가 사소한 중간 결정을 하지 않아도 되도록 구현, Android Emulator와 iPhone/11-inch iPad Simulator 실제 플레이, 문제 수정, 필요 시 로그인된 Chrome/Midjourney를 이용한 아트 제작, 재플레이를 반복하라. 시작 시 Chrome, Computer Use, Android Emulator, Xcode/iOS Simulator 연결을 실제로 확인하고 없는 권한을 있다고 가정하지 마라. 제작 중에는 실물 iPad를 빌드·설치·테스트 대상으로 사용하지 마라. Android와 iOS Simulator의 전체 회귀를 통과한 출시 후보가 완성된 뒤에만 실물 iPad 최종 검수를 별도 단계로 제안하라. 기존 working tree와 확정 시나리오를 보존하며 remote push, reset, revert, clean을 하지 마라.
