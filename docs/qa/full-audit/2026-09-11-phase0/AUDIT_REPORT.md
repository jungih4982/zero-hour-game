## 1. 실제 조사 범위와 판정 방식
- 활성 진입점, 전체 70개 런타임 장면의 본문/선택/연결, 순수 엔진·조사·추론·죽음/리셋, 저장 구조, 주요 화면 표시/입력 코드를 조사했다.
- CANON v02, FULL_SCENARIO_MASTER, 분기/상태 계약, source priority, continuity QA, handoff를 읽었다. 상세 원문 `docs/story/LOOP2_SEOYUN_DID_NOT_KNOW.md` 4-111~4-152와 production/v02/scripts의 CH03~CH07을 장면 순서대로 읽었다. CH00/CH01/Loop2 최초 개입 문서는 상세 원문이 아닌 현재의 연결/안내 문서임을 구분했다. 대화에서 먼저 승인되었다는 초반 상세 원문 원본은 저장소 자료만으로 독립 검증할 수 없었다.
- MASTER_GDD는 앞부분과 관련 규칙, PRODUCTION_ROADMAP, VISUAL_BIBLE, CODEX_WORKFLOW 및 아트 승인 주장 문서를 대조했다. 운영 문서 일부는 필요한 절만 읽었다. docs 전체 및 레거시 전체 행을 읽었다고 주장하지 않는다.
- `assets/` 안 이미지 95개를 목록화하고 비교 시트로 모두 열람했다. 그중 기준/현재 캐릭터 26개는 인물별 얼굴/몸 비교, 배경/CG 17개는 장면 비교, 나머지 52개는 후보/레거시/유니폼/아이콘 비교다. 루트의 외관 이미지 1개는 assets 외관 파일과 동일 hash인 별도 복사본이다.
- **95개 열람은 축소 시트 관찰 범위다.** 모든 픽셀/알파를 정밀 검사한 것은 아니다. 민서 현재 스프라이트는 원본과 밝은/회색 배경의 알파 비교도 직접 확인했다.
- 현재 코드 debug APK를 Android API35 에뮬레이터에 새 설치하고 Computer Use로 정상 UI 플레이했다. GUI 범위는 첫 밤부터 Loop 2 B1 조사 진입까지이며 정확한 장면별 상태는 COVERAGE.csv 및 GUI_PLAY_LOG.md에 있다.
- `OBS-GUI`: 화면/정상 입력 직접 관찰. `OBS-CODE`: 현재 소스·문서·에셋 직접 관찰. `SIM`: 현재 코드 순수 시뮬레이션. `INFERENCE`: 근거에서 추정한 영향. `PROPOSAL`: 미적용 수정/편집안.
- P0는 진행 불가/저장 손상/심각한 조기 진실 노출 등, P1은 정합성/정체성/핵심 경험 문제, P2는 국소 표시/연출 문제로 사용했다. **이번 GUI 범위에서 확정 P0 크래시나 저장 손상은 발견하지 못했다.** 미플레이 구간에 없다는 뜻은 아니다.
