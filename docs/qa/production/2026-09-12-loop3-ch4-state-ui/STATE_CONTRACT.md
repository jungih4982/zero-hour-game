# Loop3 기억과 소지품 계약

## 시작 증거

원본 `../2026-09-12-f01-dual-art/EVIDENCE/fresh-loop3-memory-choice.sqlite` SHA256:
`752b1f562e5604ddf14e60170aa8b43b270ae39a871113de6ef62cd3bc53d17e`.

`SCENE_CH3_RESET_2123`, Loop3, CAR, offset0=21:23, saveVersion5, clock.contractVersion1, standard, lastBeatIndex8. itemIds=[], 기억3/단서19/추론4, BAND_CUSTODY_YUJIN=true, TRUST_YUJIN_PROGRESS=1, MINSEO_SAW_WATCH=true. 물리 손목밴드와 B1 카트 단서는 없다. 첫 입력은 `USE_MEMORY_0106_SEAL`이다.

원본은 수정하지 않았다. byte copy를 이번 작업의 격리 기기 emulator-5580에만 복원했다. 수정 전에도 선택은 가능했으나 payoff `usableFrom=210`과 모순되었다. 따라서 ‘선택이 막혔다’고 보고하지 않는다. CH4 목표 뒤 choices=[]가 실제 진행 정지 원인이었다.

## 기억 메타데이터와 소비

| 구분 | 수정 전 | 수정 후 |
|---|---|---|
| 획득 | Loop2 01:06 사망, sourceSceneId 유지 | 동일 |
| 선택 조건 | MEMORY_0106_SEAL 획득 여부 | 동일; 미획득 시 선택 없음 |
| 지식 사용 | 실제 offset0 가능, 메타데이터 usableFrom210 | 하한 미지정. 획득한 기억을 미리 활용 |
| 사건 | 01:06=offset223 | payoff.eventTime223로 명시; clock 사건과 일치 |
| 선택 효과 | 회피 계획 플래그와 CH4 진입 | 동일. 01:06 사건/사망/아이템을 조기 실행하지 않음 |
| 현장 기록 | 설명 축약/사건 시점 구별 부족 | 전체 설명과 ‘사건 01:06 · 기억은 미리 활용할 수 있다’ |
| v5 저장 로드 | 복제된 옛 payoff가 남음 | v6에서 해당 기억 payoff만 교체; 다른 저장 내용 보존 |

`src/store/narrativeSave.ts`의 v3/v4 호환 처리는 기존 F01 계약을 유지한다. v5 clock은 시각과 events까지 그대로 보존한다. 사용자의 구시계 저장을 임의의 정상 시각으로 고치지 않는다. 실제 v5 호환 검사와 최종 번들 새 게임 검사는 별도다.

이번 수정은 상태 수명과 잘못된 소비처에 한정한다. 존재하지 않았던 손목밴드가 과거 CH3에서 맡겨졌다는 서사 모순까지 해결한 것은 아니다. [최소 재획득 권고안](CREATIVE_DECISIONS.md)을 참고한다.
